# 10 - Role Personas and Resume Strategy

This document lets a basic Composer model tailor the resume for different job types without needing to redo research every time. Use this as local knowledge before editing `latex/sections/*.tex`.

## Universal Resume Strategy

Rithwik's strongest positioning is not pure generic SWE and not pure sales. His best market fit is:

```text
Customer-facing technical operator who can discover business pain, design/configure/integrate B2B SaaS solutions, support enterprise deployments, and translate field learnings into product/engineering feedback.
```

This maps especially well to:

- Solutions Engineer
- Forward Deployed Engineer
- Implementation / Solutions Consultant
- Solutions Architect, especially implementation-heavy or application/integration-oriented roles
- Software Engineer roles that value customer-facing product implementation, integrations, infra, internal tooling, and AI workflows
- PM / TPM roles where hands-on technical delivery and stakeholder execution matter

## Persona Selection Rules

When given a JD, first classify the role into one primary persona and one optional secondary persona.

Examples:

```text
Application Architect at AbbVie → Primary: Solutions Architect / Solutions Engineer; Secondary: Enterprise Software / Implementation
Forward Deployed Engineer at AI startup → Primary: FDE; Secondary: Software Engineer / Solutions Engineer
Solutions Engineer at B2B SaaS company → Primary: Solutions Engineer; Secondary: Implementation Consultant
Technical Program Manager → Primary: TPM; Secondary: Customer-facing Software Delivery
Product Manager, AI / Industrial → Primary: PM; Secondary: Solutions / Technical Delivery
```

Then tailor bullets and skills toward the primary persona while preserving transferable strengths from the secondary persona.

# 1. Solutions Engineer

## What the resume should prove

A Solutions Engineer resume should prove that Rithwik can:

- Understand customer pain points and workflows
- Run technical discovery
- Demo products in a tailored way
- Translate technical features into business value
- Validate integrations and technical feasibility
- Partner with sales, product, engineering, and customer success
- De-risk implementation and adoption
- Communicate clearly with technical and non-technical stakeholders

## Emphasize

- 50--70 tailored pre-sales demos per year
- Discovery/configuration workshops
- Operational pain point translation
- Feature/value messaging
- Product feedback from customer conversations
- Integrations with SAP/ERP, CMMS, historians, alarms/events, equipment logs
- Training/admin enablement
- Multi-site deployments and post-go-live support

## Best Adatafy bullet order for Solutions Engineer

1. Pre-sales technical demos / value messaging
2. End-to-end implementations
3. Discovery/configuration workshops
4. Technical integrations and validation
5. Feature lifecycle / customer requirements
6. AI assistant workflows if JD mentions AI/automation
7. Support/training/adoption
8. Automation/tooling if technical depth matters

## Keywords to consider

- technical discovery
- pre-sales
- product demo
- technical validation
- proof of concept / POC
- solution design
- customer requirements
- value messaging
- stakeholder management
- integrations
- implementation
- adoption
- enablement

## Do not overdo

Do not make this sound like a quota-carrying sales resume. Keep it technical.

# 2. Software Engineer

## What the resume should prove

A Software Engineer resume should prove that Rithwik can:

- Build and maintain technical systems
- Work with APIs, databases, scripts, automation, and integrations
- Debug issues through logs, data checks, reproductions, and root-cause analysis
- Own features through requirements, implementation, testing, and release
- Operate in enterprise environments with real users and reliability constraints

## Emphasize

- REST/JSON APIs
- Python/PowerShell tooling
- SQL Server / T-SQL queries
- Postman testing
- Integrations with enterprise systems
- Structured logging and error handling
- Data transformation/validation
- CI/CD, Git, Jira, Confluence
- AWS EC2, Windows VMs, hybrid deployments
- LLM assistant workflows if the job is AI-adjacent

## Best Adatafy bullet order for Software Engineer

1. Technical integrations / APIs / enterprise systems
2. Python/PowerShell automation tooling
3. SQL Server / T-SQL / data/reporting if relevant
4. Feature lifecycle / requirements to release
5. Debugging / support / root-cause analysis
6. AI/LLM assistant workflows
7. End-to-end implementations for domain/product context
8. Discovery/demo bullets only if role values customer-facing experience

## Keywords to consider

- API integration
- backend
- automation
- scripting
- SQL
- data validation
- logging
- debugging
- root cause analysis
- feature development
- system design
- cloud
- infrastructure
- CI/CD

## Do not overdo

Do not pretend this is a traditional product-team SWE resume with years of pure coding if the JD requires deep production backend ownership. Be honest and frame around integrations, automation, enterprise deployment, and customer-facing technical ownership.

2. Technical integrations / APIs / enterprise systems
3. Onsite discovery / workflow mapping
4. Custom feature lifecycle / user pain points / UAT
5. Automation tooling / scripts / deployment repeatability
6. AI/LLM assistant workflows
7. Post-go-live support / debugging / adoption

## Keywords to consider

- customer-embedded
- field engineering
- deployment
- implementation
- integrations
- customer workflows
- production / operational systems
- technical discovery
- rapid prototyping
- ambiguous environments
- product feedback

# 5. Solutions Architect / Application Architect

## What the resume should prove

A Solutions Architect resume should prove that Rithwik can:

- Design fit-for-purpose technical solutions
- Map business requirements to system architecture
- Understand integration patterns across enterprise systems
- De-risk deployment in regulated/complex environments
- Communicate designs to stakeholders
- Support implementation, validation, and production adoption

## Emphasize

- Solution architecture diagrams
- Integration across SAP/ERP, CMMS, historians, alarms/events, equipment logs
- REST/JSON APIs
- SaaS/on-prem/hybrid deployments
- SQL Server / reporting / data exports
- SSO / Active Directory
- UAT/validation
- Regulated or operational environments such as pharma/utilities/chemicals

## Best Adatafy bullet order for Solutions Architect

1. Solution design / architecture / implementation ownership
2. Integrations / enterprise systems / APIs
3. Discovery workshops / process mapping / stakeholder alignment
4. SQL Server / reporting / data workflows if data architecture matters
5. SSO/AD, SaaS/on-prem/hybrid, infra if relevant
6. Feature lifecycle / UAT/release
7. Support/runbooks/adoption
8. Pre-sales/demo bullet if customer advisory is part of JD

## Keywords to consider

- solution architecture
- application architecture
- enterprise systems
- integration architecture
- technical design
- data flows
- APIs
- cloud / hybrid
- security / SSO
- scalability
- validation
- stakeholder alignment

## Do not overdo

Be careful with the word “architected.” Use it when he truly designed solution architecture, integration approach, workflow design, or deployment structure. Do not imply he was a formal enterprise architect unless the JD language supports that framing.

# Persona Comparison Table

| Persona | Primary Signal | Best Proof from Rithwik's Resume | Risk to Avoid |
|---|---|---|---|
| Solutions Engineer | Demos + discovery + technical validation | 50--70 demos/year, workshops, integrations | Sounding too salesy |
| Software Engineer | Build/integrate/debug/automate | REST APIs, SQL, Python/PowerShell, logging | Overclaiming deep product SWE scope |
| FDE | Customer-embedded engineering outcomes | End-to-end deployments, field integrations, support | Sounding like pure consultant |
| Solutions Consultant | Implementation + configuration + adoption | UAT, go-live, hypercare, training, process mapping | Removing technical edge |
| Solutions Architect | Technical design + enterprise integrations | Architecture diagrams, SAP/CMMS/historians/APIs | Overusing “architected” |
| Product Manager | User pain → requirements → iteration | Feature lifecycle, success criteria, product feedback | Claiming formal PM title |
| TPM | Cross-functional technical delivery | Jira, UAT/release, stakeholder coordination | Becoming non-technical PM |

# Low-Token Persona Decision Process

When tailoring, the Composer agent should do this quickly:

1. Read JD title and responsibilities.
2. Pick the primary persona from this file.
3. Pick the secondary persona only if obvious.
4. Choose the bullet ordering rules for the primary persona.
5. Use JD language only where it maps to real experience.
6. Edit only content files.
7. Compile and check one-page layout **without** editing `latex/resume-style.sty` unless a formatting change was explicitly approved.

Do not conduct additional web research unless:

- The JD link cannot be read and the role/company is unclear.
- The company/product is unfamiliar and materially changes how the resume should be framed.
- The JD uses a role title that is not covered in this doc.
- The user explicitly asks for research.

# 13 - Research Notes for Role Best Practices

This file summarizes external resume and role research so the Cursor agent does not need to repeatedly browse the web.

## General Resume Bullet Best Practices

Reliable career-center guidance generally agrees on this structure:

- Start bullets with strong action verbs.
- Provide context for what was done.
- Quantify scope and outcomes where possible.
- Explain the result or value of the work.
- Avoid vague responsibility language.

Use the local bullet formula:

```text
Action Verb + Work Done + Technical / Business Context + Scope / Scale + Outcome / Value
```

## Software Engineer Resume Best Practices

A strong software engineering resume should show:

- Technical proficiency
- Specific projects/systems built
- Business or user impact
- System design/problem-solving ability
- Debugging, reliability, and production ownership where true
- Concise, ATS-readable skills

For Rithwik, the strongest SWE angle is integrations, automation, SQL/data workflows, enterprise deployments, API testing, and customer-facing technical ownership.

## Solutions Engineer Resume Best Practices

A strong Solutions Engineer resume should show:

- Technical depth
- Customer discovery
- Demo/presentation ability
- Business-value translation
- Integrations/technical validation
- Sales/product/engineering collaboration
- Customer empathy and problem solving

For Rithwik, the strongest evidence is 50--70 demos/year, onsite discovery workshops, process maps, solution architecture diagrams, enterprise integrations, and product feedback loops.

## Forward Deployed Engineer Resume Best Practices

A strong FDE resume should show:

- Customer-embedded technical ownership
- Ability to turn ambiguous customer problems into deployed solutions
- Production/customer workflow integration
- Fast iteration and technical problem solving
- Feedback loop from field to product/engineering
- High autonomy and cross-functional execution

For Rithwik, this is a high-fit persona because his experience already combines deployment ownership, discovery, integrations, support, training, and field feedback.

## Solutions Consultant / Implementation Consultant Best Practices

A strong resume should show:

- Requirements gathering
- Process mapping
- Configuration/implementation
- UAT/go-live/hypercare
- Training and customer enablement
- Stakeholder communication
- Technical troubleshooting

For Rithwik, emphasize end-to-end implementation lifecycle, discovery/configuration workshops, UAT/validation, training, runbooks, and multi-site support.

## Solutions Architect / Application Architect Best Practices

A strong resume should show:

- Architecture/design thinking
- Enterprise integration patterns
- Cloud/hybrid/on-prem context
- Stakeholder communication
- Technical advisory
- Scalable, secure, maintainable designs
- Ability to translate business requirements into technical solutions

For Rithwik, emphasize solution architecture diagrams, integration design, SAP/ERP/CMMS/historian workflows, REST/JSON APIs, SQL Server, SSO/AD, and SaaS/on-prem/hybrid deployments.

## Product Manager Best Practices

A strong PM resume should show:

- User/customer discovery
- Product requirements
- Prioritization and roadmap thinking
- Success metrics
- Cross-functional partnership
- Customer/business impact
- Iteration based on feedback

For Rithwik, emphasize custom MES feature lifecycle, pain point discovery, success/acceptance criteria, product feedback from demos, and AI assistant prompt/product iteration.

## Technical Program Manager Best Practices

A strong TPM resume should show:

- Cross-functional technical execution
- Delivery ownership
- Scope/milestones/risks/dependencies
- Success metrics
- Stakeholder communication
- Technical credibility
- Launch/release/UAT coordination

For Rithwik, emphasize end-to-end implementations, Jira backlogs, phased rollouts, UAT/validation, stakeholder coordination, runbooks, training, and delivery methodology.

## Practical Rule for Rithwik's Resume

Do not force the resume into one persona so hard that it loses its unique value.

His differentiator is the overlap:

```text
Software Engineering + Solutions Engineering + Implementation + Product/Program Execution + Industrial AI/Digital Transformation
```

That overlap is rare and should remain visible in almost every tailored version.
